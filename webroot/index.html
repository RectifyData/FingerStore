Android ID / SSAID

Per-app · Android 8+

Edit the 64-bit Android ID seen by a selected app. Only an existing SSAID entry can be changed. Changes are staged and installed before SettingsProvider starts on your next reboot. No live database editing.

Use a package already installed and listed in Android's SSAID database. Do not select system apps.
Sync SSAID with saved build fingerprint

Optional. Derives a stable, app-specific 16-digit hex ID using the selected fingerprint and a locally generated secret salt. Changing the fingerprint restages the selected app ID.

Available when sync is off. Per-app ID is different from Settings.Secure's legacy system Android ID.
Checking per-app ID support…

The first edit creates an original SSAID database backup. A source-hash check prevents overwriting other settings changes. If it detects a mismatch, the boot operation is skipped. Restoring an app ID also requires a reboot. Unlike systemless build-property overrides, an applied SSAID edit changes Android's private settings database and may persist even if this module is disabled; explicitly restore first if needed.

Keybox loader

Local inspection

Custom, offline XML/PEM loader for inspecting a keybox file you own. The file stays in WebUI memory and is never uploaded, saved into the module, or passed to shell.

No keybox loaded. Choose a file to check its structure and the algorithms/certificate counts.
Hardware-backed attestations are signed by KeyMint's TEE/StrongBox or a trusted provisioning service. The profile vault below can switch XML keyboxes for a separately installed Oh My Keymint software provider, but cannot turn software signing into genuinely hardware-backed attestation.
The document picker above is for local inspection only. To import securely, copy your private XML to a root-readable file yourself; the WebUI deliberately never embeds private keys in shell commands.
A short label identifying this locally stored keybox.
Checking optional software-provider integration…
A software provider must already be installed and enabled. No KeyMint services are replaced or restarted by this module. Deploying a keybox can affect app sign-in/security checks; always retain a backup.

Integrity stability diagnostics

Read-only

When Play Integrity passes, capture a baseline. If labels disappear later, compare the live build properties and local software-provider file state. This cannot read or change Google's server-side verdict, prove a keybox valid, or reveal a private key.

Checking local integrity signals…

A matching provider keybox file does NOT confirm it is loaded by KeyMint or accepted by Google. On Android 13+, Strong Integrity also requires device integrity and recent security updates to real partitions. This checker never reads keybox XML, app IDs, or credentials.
